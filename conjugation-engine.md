# Kotonoha Japanese conjugation engine

| Item | Value |
| --- | --- |
| Engine version | **1.0.1** |
| Public API | `src/features/dictionary/conjugation/index.ts` |
| Generation | `src/features/dictionary/conjugation/conjugation-engine.ts` |
| Recognition | `src/features/dictionary/conjugation/match-conjugation.ts` |
| License | MIT (project-authored rules and code) |

This local engine generates forms from a dictionary entry's explicit
`conjugationClass`. It never infers a verb class from spelling alone. Search
recognition uses the same generated forms as the Forms tab, so a result can
always cite the exact version, class, group, polarity, and register that
justified it.

At the import boundary, `conjugationClassFromJmdict` maps documented JMdict POS
entity codes (`v1`, the `v5*` families, `vk`, `vs*`, `adj-i`, `adj-ix`, and
`adj-na`) to this smaller internal enum. Suru-noun entries tagged only `vs` do
not become verbs unless their dictionary spelling actually ends in する.
`v5aru` selects the honorific -aru pattern; `v5r-i` selects the ある pattern.
The importer also retains exact spelling-reading restriction pairs. Generation
validates both the pair and the spelling ending and fails closed on a missing
pair or mismatch; it never constructs a spelling-reading cross-product.

## Supported classes

- Godan verbs ending in う, く, ぐ, す, つ, ぬ, ぶ, む, or る.
- Ichidan verbs ending in る.
- Explicit irregular classes for する, 来る, 行く, ある,
  いらっしゃる-type honorific verbs, and くれる.
- i-adjectives, including the いい → よ- alternation.
- na-adjectives.

## Generated forms

Verb cards include present, past, te-form, progressive, volitional, -tai, and
imperative forms. The additional section includes -tara, -ba, potential,
passive, causative, and causative-passive forms when the selected class defines
them.

i-adjective cards include present, past, te-form, adverbial -ku, -ba, and
presumptive forms, plus -tara, -sugiru, -sō, and nominal -sa forms.
Na-adjective cards include present, past, attributive -na, te-form -de,
adverbial -ni, and -nara forms, plus -tara, presumptive, -sō, and nominal -sa
forms.

Pitch values are deliberately absent from generated cells. Version 1.0.1 does
not contain a documented accent-derivation rule, so it does not copy the
dictionary-form accent onto an inflected form.

## Irregular behavior

- 行く uses 行って and 行った, while its other rows follow the godan-く pattern.
- ある uses ない for the plain negative (である becomes でない) and does not emit potential, passive,
  causative, or causative-passive rows.
- いらっしゃる-type entries use the special polite stem and imperative in
  -い (for example, いらっしゃいます and いらっしゃい). Version 1.0.1
  does not emit derived voice or potential forms for this family.
- くれる uses くれ as its direct imperative.
- 来る stores written and reading transformations separately: for example,
  来ない/こない, 来て/きて, and 来よう/こよう.

## Matching contract

A match contains the typed surface, matched written form and reading,
localized form label, dictionary-entry reference, first sourced meaning when
available, localized relationship text, rule ID, version, and source record.
Kana and fully parseable romaji are accepted as alternate query surfaces.

The engine returns no match when:

- the entry has no explicit supported class;
- an entry with variant spellings/readings has no exact imported pair;
- the spelling does not fit that class's documented ending;
- the surface was not generated by version 1.0.1; or
- one surface has multiple unsupported grammatical analyses. Ichidan and 来る
  potential/passive overlaps are searchable with a combined label.

This is intentionally a bounded conjugation engine, not a morphological
guesser or sentence parser. A future version may add a rule only with tests,
documentation, and a version change.
